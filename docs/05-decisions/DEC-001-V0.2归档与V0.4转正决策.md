# V0.02 归档与 V0.4 提升至根目录决策记录

## 1. 背景

此前仓库根目录长期保留冻结的 V0.02（Next.js 16 + Vercel Blob 单体站点），而实际持续演进的 V0.03/V0.4（pnpm Monorepo：Vite + React SPA + Hono + SQLite）位于 `platform/` 子目录下，导致以下问题：
- 仓库根目录存在两套 `package.json`、两套 `docs/` 与两套互不兼容的构建配置；
- 开发与 CI 命令都需要额外进入 `platform/` 目录；
- 文档状态与实际主版本严重脱节。

## 2. 决策内容

1. **V0.02 采用 Git 分支 + 标签永久归档**：
   - 基于既有标签 `V0.02` 创建永久归档分支 `archive/v0.2` 并推送至远端，主分支 `main` 不再物理保留 V0.02 代码文件夹，避免全局搜索与工具误读旧代码。
2. **V0.4 正式提升至仓库根目录**：
   - 将原 `platform/` 下所有工程文件、脚本、部署模板、CI 配置与文档库整体迁至仓库根目录，统一根 `package.json` 版本号为 `0.4.0`。
3. **Vercel 生产站直接接管（纯前端裁剪安装）**：
   - 在根目录新增 `vercel.json`，使用 `pnpm install --frozen-lockfile --filter @platform/web...` 与 `pnpm --filter @platform/web build` 构建静态产物并配置 SPA 路由重写。
   - **关键考量**：`apps/api` 依赖原生模块 `better-sqlite3`，通过 `--filter @platform/web...` 仅安装前端依赖，可避免 Vercel Serverless 构建环境因原生编译浪费时间或报错。

## 3. 影响与回退路径

- 后续所有开发、CI 检查与文档更新均以仓库根目录为基准。
- 如需查阅或恢复 V0.02 历史版本，可随时执行 `git checkout archive/v0.2`（或 `git checkout V0.02`）。
- 阿里云 ECS 原生全栈部署方案（`TECH-001` / `OPS-001`）保持不变，供二/三期启用后端与 SQLite 持久化时使用。
